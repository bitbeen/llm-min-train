# 大模型训练：这套小项目里的概念

参数从随机数开始，模型、分词和每一段损失都在这个目录里用 PyTorch 写完。

这份小网络能记住仓库里的几条样本，用来把整条链路跑通。它不是一份可以拿去和几千兆参数的模型比效果的权重。

---

## 1. 一段文字怎么变成训练

模型不认识汉字。它认识的是整数。

**分词。** 先按字切开，再把语料里反复挨在一起的片段合并成子词，合并 128 轮。特殊符号 `<pad>`、`<bos>`、`<eos>` 不参与合并。词表不是事先下载的。没出现过的字，编码时会直接报错，所以新句子要先写进语料。当前词表 759。

**词表。** 编号范围是 `0 .. vocab_size-1`。输入层是一张表：每个编号对应一个向量，叫词嵌入。输出层和这张表共用同一份权重，预测下一个字就是在这张表上做分类。

**上下文长度。** `Config.max_seq` 是一次最多看多少个位置。文字再接上图像块之后如果超了，前向会停下。这份配置是 128。

**因果语言模型。** 训练时位置 t 的向量要预测位置 t+1 的字。后面的字不能被看见，这靠注意力里的上三角掩码。算错了就产生交叉熵，再反向更新参数。问题部分的标签写成 -100，损失会跳过这些位置，模型只为回答负责。`causal_loss` 把标签整体左移一位，`ignore_index=-100`。

## 2. 模型里面有什么

`TinyLM` 是一个只根据前文预测下一个字的解码器，重复堆同样的层：

1. **自注意力。** 每个位置拿出查询，去看左边每个位置的键，再把对应的值加权加起来。多头是同一件事做几遍。
2. **前馈。** 注意力之后，每个位置单独过一个网络。普通层用 SwiGLU：两条支路相乘，一条过 SiLU。指定的那一层换成专家前馈。
3. **位置。** 注意力本身不知道先后。RoPE 把位置编进查询和键的旋转里，旋转角按位置事先算好，缓存在模型上。
4. **归一化与残差。** 用 RMSNorm，不减均值，只按均方根缩放。每层的输入加回输出。

**专家前馈。** 第 2 层（`moe_layer = 1`）有 4 个 SwiGLU。每个字先打分，只计算分数最高的 2 个，再按这 2 个分数加权。当前宽度大约 0.75B，精确个数在训练开头打印。另外有一项负载损失：某个专家老被选中、别的专家闲着时，把它加进总损失，避免路由塌到一个专家上。

**预训练和后面的阶段是同一套参数。** 预训练让它会接字。监督微调给它看指令和该回答的样子。偏好学习不再只背一条标准答案：DPO 拿同一问题的好回答和坏回答做对比；GRPO 让模型自己采样一组回答，用组内奖励的相对高低当优势。

**LoRA。** 原矩阵不动，旁边加一个低秩的 `BA`，只训练 `A` 和 `B`。这一阶段学的是几条新的改短句子。学完把 `BA` 加回原权重，后面的看图和工具调用继续训完整模型。词嵌入和输出层绑在一起，这两处不加 LoRA，否则新字的向量会被冻住。

**打分。** 输出层旁边有一个打分头，看回答最后一个位置，给整条回答一个分数。组内采样时，优势等于奖励减去这个分数。奖励仍然是生成结果和标准答案有多接近。打分头用均方误差去学这个奖励，所以基线是模型自己估计的，不是另训一个打分模型。

全程只有这一份权重。它自己接词、自己看图、自己决定要不要调工具。宽度大约 0.75B，精确个数在训练开头打印。

## 3. 看图和工具是怎么接上的

文本的输入是一串字向量。图片要先变成同一串序列里的向量，后面的解码器不用另写。

这里的视觉部分画的是色块：整张纯色，或者左半、右半各一种颜色。问「左边是什么颜色」时，答案必须跟着那一半走，不能只记住这句话。

1. 把图切成不重叠的小块。
2. 每块用一个卷积映射成和词向量同维的向量。
3. 这些向量接在文字前面。图像位置的标签是 -100，模型只学回答。

看图样本不多。单独训会把前面的文字回答盖掉，所以这一阶段交替回放改短和适配过的句子。

多轮对话在 `samples/dialogue.jsonl`。提示里已经有上一问和上一答，损失只算这一轮的回答。

工具调用走同一个入口 `act`。`temperature=0` 时每个位置取概率最高的子词；设成 `0.8` 就按温度采样。模型若直接把话说完，这一轮就结束。它若写出 `<工具>…</工具>`，程序才动手：

1. 解析算式。支持加、减、乘。
2. 把 `<结果>…</结果>` 接回原文。
3. 模型再看一遍，可以再调一次，或写出最终数字。最多两次调用。

所以 `2加3` 得到 5，`2乘3` 得到 6。`2加3减1` 会先算出 5，再算出 4。没写进样本的算式，例如 `4加2`，这次没有抄对。

## 4. 训练顺序

同一份参数按这个顺序更新：

| 阶段 | 在学什么 | 代码 |
| --- | --- | --- |
| 预训练 | 句子里的下一个字 | `run_lm` + `samples/pretrain.txt` |
| 监督微调 | 指令后面的回答 | `samples/sft.jsonl`，问题标签为 -100 |
| GRPO | 采样一组回答，抬高组里更接近标准答案的那几条 | `run_grpo`。奖励是字重合和前缀，不是单独的打分模型 |
| DPO | 好回答相对坏回答的对数概率差 | `run_dpo`，参考模型是这一步开始时的拷贝 |
| LoRA | 几条新的改短句子，只动低秩矩阵 | `lora.py`，结束后合并 |
| 看图 | 纯色，以及左半、右半各一种颜色 | `vision.py`，并回放文字 |
| 工具 | 自己决定直接答，还是连续调用加减乘 | `tools.py` 的 `act`，`samples/tool.jsonl` |
| 回放 | 把前面被带偏的改短句子拉回来 | 文字样本在混合批次里出现两次 |

GRPO 放在 DPO 前面，是因为刚做完监督微调时，贪心解码已经能写出那四句短回答，采样才有「好回答」可以奖励。DPO 的参考模型如果接在一个还没稳住的策略后面，好坏回答的差距不好比。

看图放在工具前面，是因为颜色是新输入，一开始梯度大。等颜色损失降下来，再学工具，回放颜色时就不会把工具格式冲掉。

## 5. 词对照

| 说法 | 指什么 |
| --- | --- |
| 从零训练 | 参数从随机数开始，先预训练再进入后面的阶段。`train.py` 走的是这条 |
| 微调 | 预训练之后继续更新同一份权重。监督微调、DPO、LoRA 都是 |
| SFT | 监督微调，标准答案写在文本里 |
| DPO | 用一对好坏回答直接改模型 |
| GRPO | 同一问题采样一组回答，用组内相对奖励做优势 |
| LoRA | 只训练附加的小矩阵，再加回原权重 |
| 专家前馈 | 多个前馈网络，每个字只用其中几个 |
| token / 词表 / 嵌入 | 文字变成编号，编号变成向量 |
| 因果语言模型 | 只根据左边的 token 预测下一个 |
| 图像块 | 图片切块后映射成的向量，接在文字前面 |
| 参数量 | 可学习数字的个数。当前宽度大约 0.75B，精确个数在训练开头打印 |
